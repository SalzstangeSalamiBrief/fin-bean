- c#-expert

Each agent will be used for their corresponding tasks

## High level folder overview

```
- readme.md
- .gitignore        # contains files/folders to ignore by git
- project/       # Contains files related to the workflow
    - workflow.md     # contains the workflow for the project and will be used by all agents
    - project.md       # The document that contains the whole spec of project and will change over time. The workflow etc. in this file will be used by all agents
    - features/        # contains all features that should be implemented
        - feature_<number>_<short_description>.<todo|active|finished>.md        # a file that contains a feature with its description
    - bugs/         # contains all bugs found
        - bug_<number>_<short_description>.<todo|active|finished>md             # a file that contains a bug
- frontend/      # Contains frontend code
    - features/ # contains a feature
        - components/       # contains the components of the feature
    - routes/   # contains tanstack router related routing
    - lib/      # contains helper functions
    - apis/      # contains autogenerated code of the api spec
    - stores/   # contains global zustand stores
- backend/       # Contains backend code
    - <project_name>/      # the solution of the backend
        - <project_name>.Api/       # the .net web api
        - <project_name>.Core/      # shared code
        - <project_name>.<layer>/
- docker/        # Contains docker related files
```

## Workflow

- the project/spec.md file contains the whole spec of the project and will change over time
- Each feature in the project/spec.md file will added to its own md file in the project/features
  - the content will be concise
- after each feature/bug is defined the user will review these files
- If a feature/bug is getting built/fixed then a new git branch \<feature\|bug\>\/\<feature_name\> will be created

### Feature files

- File name: feature\_\<number\>\_\<short_description\>.\<status\>.md
  - status
    - If the feature is planned but not started, the file name contains _todo_
    - If the feature is currently under development, the file name contains _active_
    - If the feature is implemented, the file name contains \_finished
  - the number starts at 1 and increments with each new file
- Structure:
  ```md
      # <feature_name>
      ## Description              <!-- Description of the feature -->
      ## Acceptance criteria      <!-- Acceptance Criteria -->
      ## implementation           <!-- After finishing the implementation a short summary of the implementation details is given -->
  ```

### Bug files

- File name: bug\_\<number\>\_\<short_description\>.\<status\>.md
  - status
    - If the bug is planned but not started, the file name contains _todo_
    - If the bug is currently under development, the file name contains _active_
    - If the bug is implemented, the file name contains _finished_
  - the number starts at 1 and increments with each new file

- Structure:
  ```md
      # <bug_name>
      ## Description              <!-- Description of the feature -->
      ## How to reproduce         <!-- step by step instructions to reproduce the bug-->
      ## Acceptance criteria      <!-- Acceptance Criteria -->
      ## implementation           <!-- After finishing the implementation a short summary of the implementation details is given -->
  ```
